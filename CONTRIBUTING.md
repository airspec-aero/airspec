# Contributing

Thank you for your interest in contributing to this project!

This repository defines AirSpec, an open specification for defining crew payroll and compliance rules. We welcome feedback, suggestions, and discussions that help improve the specification.

Currently, changes to the specification are managed by the repository owners. However, the specification is community-driven so we welcome feedback and suggestions. If you'd like to contribute, please follow the process below.

## Before Raising an Issue

To help keep discussions organised and avoid duplicating existing work, please:

1. **Read the documentation.** Check the existing documentation and JSON Schemas to understand the current specification and the design decisions behind it.
2. **Search existing issues.** Check whether an [issue already exists](https://github.com/airspec-aero/airspec/issues) covering your question, suggestion, or proposed change.
3. **Check the forums.** Review the [project forums](https://www.linkedin.com/groups/42821328/) to see whether the topic has already been discussed.

## Raising an Issue

If you can't find an existing issue or discussion covering your topic, please [open an issue](https://github.com/airspec-aero/airspec/issues).

When raising an issue, please include:

- **Context:** What part of the specification does your issue relate to?
- **Problem or suggestion:** What would you like to clarify, improve, or change?
- **Rationale:** Why do you think this change would be beneficial? Include examples where helpful.

Issues are the primary way to propose changes to the specification and bring them to the attention of the repository owners.

## Pull Requests

Changes to the specification are currently managed by the repository owners. Please raise an issue to discuss proposed changes before undertaking implementation work or submitting a pull request.

Thank you for helping improve the specification!
